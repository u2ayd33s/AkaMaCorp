1. 背景と結論（要約）

SharePointで 「組織のストレージがいっぱいです」 というエラーが表示された。これはテナント（組織）全体のSharePointストレージのプールを使い切った状態を指す。

結論： 容量を食っていたのは /sites/AkamaFolder サイト（当初412GB）。だが最終的な決定打は「ごみ箱を空にすること」だった。ドキュメントを削除しても、その実体（331.99GB／1,924件）がごみ箱に残ったまま容量を消費し続け、読み取り専用ロックが解除されなかった。ごみ箱を空にした瞬間に サイト0GB・ロック解除・テナント合計6.43GB まで一気に解消した。
最大の教訓： ファイルを削除してもごみ箱に入るだけで容量は1バイトも戻らない（最大93日消費し続ける）。「減らしたのに満杯のまま」なら、まず真っ先にごみ箱を疑うこと。

ビフォー / アフター

指標対処前対処後
AkamaFolder 使用量412 GB0 GB
AkamaFolder ごみ箱331.99 GB（1,924件）0 GB
テナント全体 合計420 GB 超（上限突破）6.43 GB
サイトの状態ReadOnly（読み取り専用）Unlock

開発者プログラムのテナントは容量を追加購入できないため、対処は「増やす」ではなく 「減らす（ごみ箱・バージョン・不要ファイルの削減）」 が基本となる。

2. 開発者プログラムのストレージ制限

Microsoft 365 開発者プログラムのテナントには、以下の制限がある。容量の追加・アップグレードはできない。

項目制限
テナント全体のプール容量300 GB（開発者専用テナントの上限）
OneDrive（ユーザーごと）10 GB / 開発者SKUユーザー（SharePoint枠とは別計算）
容量追加不可（Microsoftが制限する権利を留保と明記）
開発テナントは開発・テスト用の短期利用が前提（90日ごとに更新される設計）。本番用途や長期のデータ保管には向かない。本格的な容量が必要なら、アドオン購入やライセンス追加で拡張できる通常の有料サブスクリプションを使う。

3. 対処の全体像（減らす3ステップ）

「消しても容量が減らない」の主因は、ごみ箱とバージョン履歴。以下の順で進めるのが最も効率的。

1
全サイトのごみ箱を空にする（第1段階＋第2段階）。削除しても最大93日ごみ箱に残り容量を消費し続けるため。
2
容量を食っているサイトを特定する。全サイトを使用量順にランキングして犯人を絞り込む。
3
犯人サイトのバージョン履歴をトリミング／不要ファイルを削除する。実体の容量を削減する。
今回いちばん効いたのはステップ1（＋削除後の再クリア）： ファイル削除後にごみ箱を空にしたら、332GBが解放されてテナントが即座に上限以下に戻った。大きな削除をしたら、その削除分がごみ箱に入るので「もう一度ごみ箱を空にする」のが決め手になる。
反映のタイムラグ： ごみ箱を空にしても、管理センターの空き容量表示への反映は数時間〜最大48時間かかる。バージョン削除ジョブは数日かけて処理される。すぐに数字が動かなくても正常。

4. 環境準備：PnP PowerShell のセットアップ

SharePoint Online Management Shell（SPOモジュール）にはごみ箱を空にするコマンドがないため、PnP PowerShell を使う。以下は一度だけ行う初期設定。

4-1. PowerShell 7 を使う

現行の PnP.PowerShell（2.x系）は PowerShell 7.2以上が必須（Windows PowerShell 5.1では動かない）。

# PowerShell 7 をインストール（未導入の場合）
winget install --id Microsoft.PowerShell --source winget
インストール後は pwsh（PowerShell 7）を起動して以降の作業を行う。今回の実行環境は PowerShell 7.6.0。

4-2. モジュールをインストール

# 新モジュール（旧 SharePointPnPPowerShellOnline は使わない）
Install-Module PnP.PowerShell -Scope CurrentUser -Force

# 導入確認
Get-Module PnP.PowerShell -ListAvailable | Select-Object Name, Version

4-3. Entra ID アプリを登録（ClientId 取得）

2024年9月以降、Connect-PnPOnline -Interactive は独自のEntra IDアプリ登録（ClientId）が必須。一度だけ登録する（グローバル管理者権限が必要）。

Register-PnPEntraIDAppForInteractiveLogin `
  -ApplicationName "PnP-RecycleBin" `
  -Tenant "u2ayd33s.onmicrosoft.com"
注意： このコマンドに -Interactive パラメーターは存在しない（ブラウザ対話が既定）。付けると「parameter cannot be found」エラーになる。ブラウザが開かない場合は -DeviceLogin を付ける。
今回取得した ClientId：965eb559-bb17-471f-a595-8bf093d8ba09（以降の全コマンドで使用）

5. 全サイトのごみ箱を一括で空にする

SPOモジュールを使わず、PnPの Get-PnPTenantSite で全サイトを取得してループ処理する。すべてPowerShell 7内で完結する。

$clientId = "965eb559-bb17-471f-a595-8bf093d8ba09"
$adminUrl = "https://u2ayd33s-admin.sharepoint.com"

# 管理センターに接続し、全サイトを取得
Connect-PnPOnline -Url $adminUrl -Interactive -ClientId $clientId
$sites = Get-PnPTenantSite

foreach ($site in $sites) {
    Write-Host "ごみ箱を空にする: $($site.Url)"
    try {
        Connect-PnPOnline -Url $site.Url -Interactive -ClientId $clientId
        # -All = 第1段階＋第2段階の両方を空にする
        Clear-PnPRecycleBinItem -All -Force
        Write-Host "  → 完了" -ForegroundColor Green
    }
    catch {
        Write-Warning "スキップ: $($site.Url) - $($_.Exception.Message)"
    }
}
コマンド名に注意： 正しくは Clear-PnPRecycleBinItem（末尾に Item）。Clear-PnPRecycleBin は存在しない。
OneDriveも対象にする場合： Get-PnPTenantSite -IncludeOneDriveSites とする（管理URLへの接続が前提）。

6. 容量を食っているサイトを特定する

全サイトの使用量をランキング表示し、合計も算出する。これが「どのサイトが容量を食っているか」への直接の答え。

Connect-PnPOnline -Url "https://u2ayd33s-admin.sharepoint.com" -Interactive -ClientId $clientId

$all = Get-PnPTenantSite -IncludeOneDriveSites
$all |
    Select-Object Url,
        @{N='使用GB';E={[math]::Round($_.StorageUsageCurrent/1024,2)}},
        @{N='上限GB';E={[math]::Round($_.StorageMaximumLevel/1024,2)}},
        LockState |
    Sort-Object 使用GB -Descending |
    Format-Table -AutoSize

$totalGB = [math]::Round(($all | Measure-Object StorageUsageCurrent -Sum).Sum/1024,2)
Write-Host "全サイト合計使用量: $totalGB GB" -ForegroundColor Yellow

特定サイト内の内訳（ライブラリ単位）

Connect-PnPOnline -Url "https://u2ayd33s.sharepoint.com/sites/AkamaFolder" -Interactive -ClientId $clientId

Get-PnPList |
    Where-Object { $_.BaseTemplate -eq 101 } |   # 101 = ドキュメントライブラリ
    Select-Object Title, ItemCount, EnableVersioning |
    Sort-Object ItemCount -Descending |
    Format-Table -AutoSize
ブラウザで見る方法： https://<サイトURL>/_layouts/15/storman.aspx（記憶域メトリックス）を開くと、フォルダ・ファイル単位のサイズが視覚的に確認できる。

7. バージョン履歴の一括トリミング

バージョン管理ONのライブラリでは、各ファイルの古いバージョンが容量を大量に消費する。現行ファイルに触れずに古い版だけを削除できる。

Connect-PnPOnline -Url "https://u2ayd33s.sharepoint.com/sites/AkamaFolder" -Interactive -ClientId $clientId

# 自動トリミング（最新版と直近の版は保持し、古い版を削除）＝推奨
New-PnPSiteFileVersionBatchDeleteJob -Automatic -Force

# もっと積極的に：指定日数より古い版を全削除する場合
New-PnPSiteFileVersionBatchDeleteJob -DeleteBeforeDays 60 -Force
実行結果： Success. Versions specified will be permanently deleted in the upcoming days. — ジョブは数日かけて処理される。削除された版は完全削除（ごみ箱を経由しない）。

効果の確認（数日後）

Connect-PnPOnline -Url "https://u2ayd33s-admin.sharepoint.com" -Interactive -ClientId $clientId
Get-PnPTenantSite -Identity "https://u2ayd33s.sharepoint.com/sites/AkamaFolder" |
    Select-Object Url, StorageUsageCurrent
それでも大きい場合： 容量の実体は「実ファイルそのもの」。より積極的なバージョン削除（-DeleteBeforeDays 30）か、不要ファイルの削除が必要。

結論： AkamaFolder 1サイトだけで412GB。2位以下は桁違いに小さく、他は無視してよい。この1サイトの削減＝問題解決。

AkamaFolder 内のライブラリ内訳

ライブラリアイテム数バージョン管理
ドキュメント265,878ON ← 容量の実体
画像412ON
サイトのリソース ファイル26ON
スタイル ライブラリ0ON

「ドキュメント」ライブラリの26万件超のファイルとそのバージョン履歴が412GBの正体。ここに対してバージョントリミングを実行し、その後ファイル本体も削減した。

決定打：ごみ箱に隠れていた 332GB

ファイルを削減してもなお「組織のストレージがいっぱいです。SharePoint サイトは現在読み取り専用です」が出続けた。原因はごみ箱だった。Get-PnPRecycleBinItem で確認すると、削除したはずのファイルがごみ箱に残り、依然として容量を消費していた。

PS> $items = Get-PnPRecycleBinItem
PS> "{0} 件 / 合計 {1:N2} GB" -f $items.Count, (($items | Measure-Object Size -Sum).Sum/1GB)
1924 件 / 合計 331.99 GB   ← これが「減らしたのに満杯」の正体

Clear-PnPRecycleBinItem -All -Force で空にした直後の確認結果：

Url                 : .../sites/AkamaFolder
StorageUsageCurrent : 0          # 412GB → 0
LockState           : Unlock     # 読み取り専用が自動解除

# テナント全体の合計
全サイト合計使用量: 6.43 GB   # 420GB超 → 6.43GB。完全解決。
解決： ごみ箱を空にした瞬間に、サイトは0GB・ロック解除、テナント全体は6.43GBまで低下。読み取り専用状態は使用量が上限を下回ると自動的に解除される（手動解除は不要）。
不可逆： ごみ箱を空にした分（第2段階含む）は完全削除され復元できない。実行前に、消したくないファイルが混ざっていないか確認すること。

9. 遭遇したエラーと対処（トラブルシュート集）

エラー原因対処
Connect-PnPOnline がモジュール SharePointPnPPowerShellOnline で見つかったが読み込めない 廃止された旧モジュールを参照している PowerShell 7 で PnP.PowerShell を導入。旧モジュールは Uninstall-Module SharePointPnPPowerShellOnline -AllVersions
Connect-SPOService / Get-SPOSite is not recognized SPOモジュールはWindows PowerShell 5.1専用でPS7に無い SPOを使わず Get-PnPTenantSite に置き換え、PS7内で完結させる
Register…: parameter -Interactive が見つからない 登録コマンドに -Interactive は存在しない -Interactive を外す（ブラウザが既定）。開かない時は -DeviceLogin
Clear-PnPRecycleBin is not recognized コマンド名の誤り 正しくは Clear-PnPRecycleBinItem（末尾 Item）
Access is denied (E_ACCESSDENIED) ／ unauthorized operation そのサイトのサイトコレクション管理者に入っていない、またはサイトがロック状態 Set-PnPTenantSite -Identity <url> -Owners <自分のUPN> で管理者追加。GUIなら管理センター→アクティブなサイト→メンバーシップ
指定されたユーザー … が見つかりませんでした UPNのプレースホルダー（例文）を実値に置換していない ログイン中アカウントを自動取得して使う（下記）
Site has exceeded its maximum file storage limit テナントプール（300GB）が満杯で書き込み操作が弾かれる 個別サイトの問題ではなくテナント満杯の症状。容量削減を進める

ログイン中アカウント（UPN）を自動取得する

Connect-PnPOnline -Url $adminUrl -Interactive -ClientId $clientId
$login = (Get-PnPProperty -ClientObject (Get-PnPContext).Web -Property CurrentUser).LoginName
$adminUpn = $login -replace '^i:0#\.f\|membership\|',''
Write-Host "あなたのアカウント: $adminUpn" -ForegroundColor Cyan

10. 補足：一般テナント／GUIでの対処

ごみ箱をGUIで空にする

サイトの「サイトコンテンツ」→「ごみ箱」で第1段階を空にし、そのページ下部の「第2段階のごみ箱」リンクから第2段階も空にする。第2段階にはサイトコレクション管理者権限が必要。

容量を確認する（管理者）

SharePoint管理センター →「アクティブなサイト」で、右上に組織全体の使用量、各サイトの「記憶域」列で個別使用量を確認できる（反映は24〜48時間遅れ）。

一般ユーザーの場合

組織全体の容量は管理者しか増やせない。自分のサイトが上限に近い場合は、サイト設定→「記憶域メトリックス」→「追加のクォータを要求」で管理者にメール送信できる。

有料テナントで容量を増やす

（開発テナントでは不可だが）通常の有料テナントは、Microsoft 365 Extra File Storage アドオンの購入、またはライセンス追加（1個あたり+10GB）で拡張できる。非アクティブなコンテンツのアーカイブ（クォータ非計上）も有効。
