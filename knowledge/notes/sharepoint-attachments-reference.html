実体と Attachments 列

添付ファイルはアイテムのプロパティとして扱われる。

リストには Attachments（内部名も同じ）というブール型の組み込み列があり、持っている情報は「添付があるかどうか」だけ。ファイル名や URL はこの列には入らない。実ファイルの一覧は AttachmentFiles コレクションから取得する。

リストのバージョン管理を有効にしている場合、アイテムのバージョンを戻すと添付ファイルの構成も戻る。ただし残るのは「そのバージョン時点でどのファイルが付いていたか」で、ファイル自体の版管理はされない。

検索については添付ファイルの中身もクロールされるため、KQL で本文にヒットさせることは可能。

添付機能そのものを無効化する

MERGE /_api/web/lists
fetch("/_api/web/lists/getbytitle('リスト名')", {
  method: "POST",
  headers: {
    "Accept": "application/json;odata=nometadata",
    "Content-Type": "application/json;odata=nometadata",
    "X-RequestDigest": digest,
    "X-HTTP-Method": "MERGE",
    "IF-MATCH": "*"
  },
  body: JSON.stringify({ EnableAttachments: false })
});

既に添付があるアイテムのファイルは、無効化しても消えず参照だけ残る。切り替えは影響範囲を確認してから。

ライブラリとの違い

できないことを先に把握しておくと設計を間違えにくい。

添付ファイルドキュメントライブラリ
メタデータ列付けられない付けられる
バージョン管理ファイル単体では不可可能
チェックイン / アウト不可可能
フォルダー階層ItemId 直下のみ自由
共有リンク発行実質不可可能
同名ファイルの上書き削除してから追加バージョンで上書き
サイズ上限ライブラリより小さい250 GB
グリッド編集での追加不可—
検索での本文ヒットするする

サイズ上限は公式値を都度確認する。添付ファイルの上限はライブラリのアップロード上限とは別枠で、従来 250 MB 程度とされてきた。数百 MB 級を扱う想定なら添付は選ばず、ライブラリ + 参照列にする。

REST API

追加はバイナリを直接ボディに載せる。取得は $expand が効く。

取得

GET 単一アイテムの添付一覧
/_api/web/lists/getbytitle('リスト名')/items(1)/AttachmentFiles
GET 一覧取得でまとめて展開
/_api/web/lists/getbytitle('リスト名')/items
  ?$select=Id,Title,Attachments,AttachmentFiles/FileName,AttachmentFiles/ServerRelativeUrl
  &$expand=AttachmentFiles
  &$filter=Attachments eq 1

Attachments が false のアイテムは AttachmentFiles が空配列で返る。件数が多いリストでは $filter=Attachments eq 1 を併用して無駄な展開を避ける。ファイルへのリンクは ServerRelativeUrl をそのまま使う。

追加

POST AttachmentFiles/add
// file は File オブジェクト（input[type=file] など）
const url = `/_api/web/lists/getbytitle('リスト名')/items(1)`
  + `/AttachmentFiles/add(FileName='${encodeURIComponent(file.name)}')`;

await fetch(url, {
  method: "POST",
  headers: {
    "Accept": "application/json;odata=nometadata",
    "X-RequestDigest": digest
  },
  body: await file.arrayBuffer()   // バイナリをそのまま渡す
});

ファイル名の扱いが最大のハマりどころ。FileName は URL パス内のリテラルなので encodeURIComponent が必須。日本語名はこれを忘れると 400 になる。

さらにファイル名にシングルクォートが含まれる場合は ''（2 個重ね）にエスケープする。jQuery の $.ajax を使うなら processData: false を指定して、バイナリを文字列化させない。

削除と置き換え

POST + X-HTTP-Method: DELETE
await fetch(`/_api/web/lists/getbytitle('リスト名')/items(1)`
  + `/AttachmentFiles/getByFileName('${encodeURIComponent(name)}')`, {
  method: "POST",
  headers: {
    "X-RequestDigest": digest,
    "X-HTTP-Method": "DELETE",
    "IF-MATCH": "*"
  }
});

同名ファイルを上書きする API はない。削除 → 追加の 2 ステップで置き換える。完全削除ではなくごみ箱に送る場合は、末尾を /recycleObject にする。

PnP PowerShell

一括移行や棚卸しはこちらが速い。

追加 / 取得 / 削除
Add-PnPListItemAttachment    -List "リスト名" -Identity 1 -Path "C:\temp\doc.pdf"
Get-PnPListItemAttachment    -List "リスト名" -Identity 1 -Path "C:\out" -Force
Remove-PnPListItemAttachment -List "リスト名" -Identity 1 -FileName "doc.pdf" -Force

Get-PnPListItemAttachment は -Path にローカルフォルダーを渡すとファイルとして書き出す。全アイテムを回して添付の有無を棚卸しするなら、Get-PnPListItem の結果に対して Attachments 列で絞ってから実行する。

Power Platform

Power Apps は添付をフォームから切り離せない。ここが設計の制約になる。

Power Apps

添付ファイルコントロールは SharePoint リストのフォーム（Form.DataSource 経由）でしか機能しない。Patch で添付ファイルを直接操作することはできない。

フォームを使わない独自 UI で添付を扱いたい場合は、Power Automate をカスタムコネクタのように呼び出し、その中で SharePoint コネクタか REST を叩く構成にする。表示だけなら、フローで添付ファイル名と URL を取得してギャラリーに流す。

Power Automate

  • 添付ファイルの取得 — ファイル名と ID の一覧を返す。中身は含まれない。
  • 添付ファイルのコンテンツの取得 — 上記の ID を渡して本体を取る。

2 段構えになるため、Apply to each の中でコンテンツ取得を回す形になる。件数が多いと実行時間に直結するので、必要なファイルだけ絞り込んでからループに入れる。

列・ビューの書式設定

できるのはアイコンの出し分けまで。

Attachments はブール値として評価されるので、クリップアイコンの表示制御はできる。

列の書式設定 JSON
{
  "elmType": "span",
  "attributes": {
    "iconName": "=if([$Attachments], 'Attach', '')"
  }
}

一方で、添付ファイル名やそのリンクを書式設定 JSON から直接参照する手段はない。ビュー上にファイル一覧を見せたい要件がある場合は、Power Automate で複数行テキスト列にファイル名を書き出しておき、その列を書式設定でリンク化する回避策をとる。

ハマりどころ

実装時に踏みやすい順に。

  • 日本語ファイル名で 400 が返るFileName の encodeURIComponent 漏れ。シングルクォートは '' にエスケープする。
  • アップロードした添付が壊れているバイナリが文字列化されている。$.ajax なら processData: false、fetch なら ArrayBuffer をそのまま body に渡す。
  • 同名ファイルの再アップロードが失敗する上書き API はない。先に削除する。
  • 新規アイテム作成と同時に添付できない添付先の ItemId が必要。アイテムを作成 → 返却された Id で添付、の順序になる。
  • グリッド（クイック編集）で添付を追加できない詳細ペインかフォームを開く必要がある。運用手順に書いておく。
  • 添付が多いリストで一覧表示が重い$expand=AttachmentFiles を無条件に付けている。Attachments eq 1 で絞る。
  • ファイルの差し替え履歴を追えない仕様。追跡が要件ならライブラリに寄せる。

使い分けの目安

迷ったらこの線で判断する。

添付ファイルで足りる

  • アイテムの証跡として付随するだけ（申請書の控え、写真）
  • ファイル単体で検索・共有される想定がない
  • 1 アイテムあたり数点、サイズも小さい
  • アイテムを消したら一緒に消えてよい

ライブラリに寄せる

  • ファイルにメタデータや分類を付けたい
  • 差し替え履歴を残したい
  • ファイル単体で共有リンクを配りたい
  • サイズが大きい、または点数が多い
  • Power Apps 側で添付 UI を自作したい

ライブラリを選ぶ場合は、リスト側に参照列（ハイパーリンク列やルックアップ）を置いて紐づける構成が扱いやすい。
