## 2026-11-27

## DECISION
- ヒストリーサイトのポップアップ通知は、種類ごとに出どころを分ける: 今日は何の日＝Wikipedia（取れなければ今月の歴史）／今週のストーリー＝HISTORY ARCHIVE から週番号で1件／創業者の言葉・お知らせ＝新しいリスト AsicsPopupMessages。アーカイブだけでは創業者の言葉の置き場が無く、リストだけでは内容を二重管理になるため
- 表示は「種類を先にランダムに選び、その中から1件」: 件数の多い種類に偏らないようにするため。取れなかった種類は飛ばして、次の種類を試す
- 「1つのタブでは1回だけ」をやめ、「再読み込みまでは1回だけ」にした: sessionStorage だと同じタブの再読み込みで二度と出ず、確認できなかったため。ページ内の移動（SPA）で戻ったときは出さない
- SharePoint の書き込み（リスト作成・データ投入・JS/CSS のアップロード）は、PnP ではなく画面操作で行う（ユーザー指示）。PnP は読み取りの確認だけ。MyCorp/CLAUDE.md・scriptloader/CLAUDE.md・05_sharepoint/CLAUDE.md に明記
- ScriptLoader 用の JS・CSS は、冒頭の仕様ヘッダー・ブロック見出し・関数や設定の説明をコメントで詳細に書く（お手本は mare-group の SitePages__Home.js）。CLAUDE.md と scriptloader スキルに明記
- ヒストリーサイトのハートの見た目: 今月の歴史のハート（#pHeart / .pick .heart）は、背景・枠線・影をすべて無しにする（白いカードの上に置くため）。一覧カードのハート（.rcard .heart）は、影だけ無しにして、白い丸の背景は残す（写真の上でも見えるようにするため）
- ポップアップ（#XSP-history-popup）の幅を、最大340px から最大440px（min(440px,calc(100vw - 16px))）に広げた: 本文が読みやすくなるように。狭い画面では、これまでどおり画面幅−16px に収まる。CSS のコメント（最大340px）も合わせて修正
- PR のマージ順: 日報の PR（AkaMaCorp #19）を先にマージし、そのあとで MyCorp のポインタ PR（#27）に AkaMaCorp の分も足してマージした: 先に #27 をマージすると、#19 のマージ後にまたポインタ更新の PR が要るため（1回で済ませる）

## INSIGHT
- 日本語版 Wikipedia には「今日は何の日」専用の API（onthisday）が無い（404）。英語版にはある。日本語は、日付のページ（「11月27日」）を MediaWiki API（action=parse、origin=*）で取り、「できごと」の節の li を切り出す。DailyGreeting.js が同じ方法を使っている
- Wikipedia の出来事をそのまま社内サイトに出すと、事件・事故などが混ざる（例：いじめ自殺事件）。語で除外するフィルターが要る。政治色のある出来事は、語では防げない
- build-sharepoint.js は CSS のコメントを全部消していた。ルール直前のコメントを引き継ぐ形に直すと、元の index.html に書いた説明が、生成される CSS に残る。ただし CSS のコメントの中に { } を書くとルールの区切りと誤認する。JS のコメントの中に */ を書くと、コメントが閉じて構文エラーになる
- PnP が使えない（D: ドライブが見えない）ときでも、ブラウザ側で fetch したファイルの SHA-256 を、手元のファイルと比べれば、アップロードの内容一致を確認できる
- ハートの台（背景）を無しにしても、押せる範囲は width / height で保てる（今月の歴史のハートは、28px のハートを 48px の範囲の中央に置いたまま、background・border・box-shadow だけ none にした）。override.css は index.html の CSS の後ろに連結されるので、同じ詳細度でも、上書きが勝つ
- 画面操作でアップロードしたときの「同じ名前のファイルがある」確認のボタン名は、ファイルの数で変わる。1ファイルのときは「置き換える／両方残す」、複数のときは「すべて置き換える／すべて残す」。1ファイルのときに「すべて置き換える」を探すと見つからず、アップロードが保留のまま残る（サーバー側のハッシュが前の版のままなので気づける）

## ERROR
- ポップアップが表示されない: 「1つのタブで1回」を sessionStorage に保存していたため、同じタブを再読み込みしても二度と出なかった（テストでは毎回消していたので気づけなかった） → 保存をやめ、ページ読み込み後の変数で管理。確認用に ?popup=wiki|week|founder|news を追加
- 自動操作のブラウザ（Playwright）で、ScriptLoader が動かない（SPLoader が未定義で、ScriptLoader のファイルを1件も読まない）: 原因は未特定。サイトの UserCustomActions は空（テナント全体展開は、ここに出ない） → ポップアップの実表示は、ユーザーの通常のブラウザで確認してもらう
- 「PnP で接続」しようとしたら D:\Claude\… のスクリプトが見つからない: D: ドライブが接続されていなかった → ブラウザ側の照合で代替
- 画面操作でアップロードしたら、結果が返らず、以降のコードも実行できなくなった: browser_run_code_unsafe の中で filechooser を待つと、ファイル選択のダイアログがツール側に開いたまま残り、「modal state を扱えない」エラーになる → ツールの browser_file_upload でファイルを渡す。そのあと、ハッシュで内容一致を確認する
- ポインタ PR のマージが「Base branch was modified」で失敗した: 直前に別の PR をマージして base（main）が動いた直後だった → 数秒待って mergeable を確認し、同じコマンドでやり直すと通った

## PATTERN
- 確認用の URL パラメータで、ランダムな動きを固定する（?popup=種類）。指定した種類を先頭で試し、取れなければ他で代用する
- 画面操作で ScriptLoader のファイルを上げる: ライブラリ（SiteAssets/ScriptLoader）を開く → 作成またはアップロード → ファイルのアップロード → 同名の確認で「すべて置き換える」（既存の新しい版として追加される）。上げたあとは、版番号とハッシュで確認する
- 日報 PR とポインタ PR が並ぶときは、日報（サブリポジトリ側）を先にマージ → ポインタ PR のブランチで submodule を最新 main に進めてコミット → マージ
- 各リポジトリの PR をマージしたあと、MyCorp でサブモジュールポインタを最新の main に更新する PR を作る
